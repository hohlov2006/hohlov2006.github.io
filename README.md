# «Мне скучно»

Сайт, который придумывает занятие. Пользователь нажимает большую кнопку **«Мне скучно»**, ИИ предлагает идею под его интересы, время суток и настроение, пользователь оценивает идею по шкале от 1 до 5, а запрос и оценка записываются в базу данных. Для партнёров (например, спортзала) есть промокоды по геолокации. Отдельная панель разработчика показывает, как ИИ справляется и что предпочитают пользователи.

Серверу не нужны зависимости: `npm install` выполнять не требуется. Нужен только **Node.js 22.13 или новее** (база данных SQLite встроена в Node).

## Что внутри

```
server.js          сервер: API, вход разработчика, статические файлы
src/ai.js          подключение ИИ (DeepSeek или любой OpenAI-совместимый API)
src/db.js          база данных SQLite, демо-данные
src/schema.sql     схема БД (копия лежит в docs/schema.sql — пригодится для отчёта)
public/            сайт: index.html (главная), admin.html (режим разработчика)
public/js/core.js  общее ядро: категории, запасной генератор, статистика, правила купонов
test/              автотесты (npm test)
render.yaml        настройки для Render.com
.github/workflows  публикация на GitHub Pages
```

## Запуск у себя на компьютере

1. Установите Node.js 22 или новее (nodejs.org), проверьте командой `node -v`.
2. Откройте папку проекта в терминале.
3. (Необязательно) скопируйте `.env.example` в `.env` и впишите свои значения.
4. Выполните `npm start` и откройте http://localhost:3000.
5. Режим разработчика: http://localhost:3000/admin.html. Без `.env` пароль `mneskuchno`, логин `admin` (смените его в `.env`).
6. Проверка проекта: `npm test` (7 тестов: генерация, оценки, купоны, защита панели, ИИ через мок).

## Как выложить сайт бесплатно, чтобы показать по ссылке

Есть два варианта. Можно сделать оба.

| | A. GitHub Pages | Б. Render.com |
|---|---|---|
| Что получится | Демо-режим без сервера | Полная версия: сервер, база, ИИ |
| ИИ | Нет, встроенный набор идей | Да, если добавить ключ |
| Где хранятся оценки | В браузере посетителя | В базе данных на сервере |
| Панель разработчика | Работает на данных браузера (admin / mneskuchno) | Работает на данных всех пользователей |
| Сложность | Очень простая | Простая |

Для защиты работы лучше **вариант Б**: он показывает настоящую архитектуру (клиент, сервер, база, ИИ). Вариант А удобен как запасной: он всегда доступен без «засыпания».

### Шаг 0. Залить проект на GitHub (нужен для обоих вариантов)

1. Зарегистрируйтесь на github.com.
2. Нажмите **New repository**, назовите, например, `mneskuchno`, тип **Public**, создайте.
3. На странице репозитория нажмите **uploading an existing file** и перетащите **содержимое** папки проекта (не саму папку, не архив). Важно, чтобы загрузились и скрытые файлы, включая папку `.github`. Если они не перетащились, используйте GitHub Desktop или команды:
   ```
   git init
   git add .
   git commit -m "Мне скучно"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/mneskuchno.git
   git push -u origin main
   ```
4. Убедитесь, что основная ветка называется `main`.

### Вариант А. GitHub Pages

1. В репозитории откройте **Settings → Pages**.
2. В поле **Source** выберите **GitHub Actions**.
3. Перейдите во вкладку **Actions**: запустится «Deploy to GitHub Pages». Дождитесь зелёной галочки (около минуты). Если ничего не запустилось, откройте этот workflow и нажмите **Run workflow**.
4. Ссылка: `https://ВАШ_ЛОГИН.github.io/mneskuchno/`. Режим разработчика: `.../admin.html`, логин `admin`, пароль `mneskuchno`.

В этом режиме сайт определяет, что сервера нет, и сам переключается на хранение в браузере. На главной внизу будет надпись «Демо-режим без сервера».

### Вариант Б. Render.com (полная версия)

1. Зарегистрируйтесь на render.com (удобно через аккаунт GitHub).
2. Нажмите **New → Web Service**, выберите репозиторий `mneskuchno` (разрешите Render доступ к нему).
3. Заполните:
   - **Runtime / Language:** Node
   - **Build Command:** `npm install` (оставьте по умолчанию)
   - **Start Command:** `node server.js`
   - **Instance Type:** Free
4. В разделе **Environment Variables** добавьте:

   | Переменная | Значение |
   |---|---|
   | `NODE_VERSION` | `22.22.0` |
   | `NODE_ENV` | `production` |
   | `ADMIN_LOGIN` | `admin` (или своё) |
   | `ADMIN_PASSWORD` | придумайте пароль разработчика |
   | `SESSION_SECRET` | любая длинная случайная строка |
   | `AI_API_KEY` | ключ ИИ (см. ниже; можно оставить пустым) |
   | `AI_BASE_URL` | `https://api.deepseek.com` |
   | `AI_MODEL` | `deepseek-v4-flash` |

5. Нажмите **Create Web Service**. Через 2–3 минуты появится ссылка вида `https://mneskuchno.onrender.com`.
6. Режим разработчика: `https://…onrender.com/admin.html`.

Можно проще: **New → Blueprint** и выбрать репозиторий. Render прочитает файл `render.yaml` и сам создаст сервис, а пароль спросит при создании.

**Что нужно знать о бесплатном Render** (проверено по документации Render):
- Если 15 минут никто не заходил, сервис «засыпает». Первый заход после паузы занимает около минуты. Откройте ссылку за пару минут до защиты.
- Диск на бесплатном тарифе **временный**: при перезапуске и засыпании база SQLite очищается. Поэтому включён `AUTO_SEED=1`: на пустой базе автоматически создаются 400 демо-записей, и панель разработчика не пустая. Демо-записи помечены «демо», их можно убрать кнопкой в панели или чекбоксом «Учитывать демо-данные».
- Нужны постоянные данные? Либо платный тариф с диском, либо внешняя база (например, Postgres). Для этого придётся заменить модуль `src/db.js`. Для учебной защиты это не требуется.

### Подключение ИИ

Сайт работает с любым **OpenAI-совместимым** API. Три переменные: `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`.

- **Без ключа** всё работает: идеи берутся из встроенного набора из 50 заготовок с учётом интересов, бюджета, времени суток и прошлых оценок. В журнале и на главной честно видно, что это не ИИ.
- **DeepSeek (официальный API)**: ключ создаётся на platform.deepseek.com, `AI_BASE_URL=https://api.deepseek.com`. Он не бесплатный: оплата по токенам, а на нашу задачу уходит очень мало (несколько сотен токенов на запрос). Названия моделей DeepSeek меняются, поэтому сверьтесь с их документацией и при необходимости поправьте `AI_MODEL`.
- **Бесплатные варианты**: у OpenRouter есть модели с суффиксом `:free` (`AI_BASE_URL=https://openrouter.ai/api/v1`, модель выберите в каталоге на openrouter.ai). Но по сообщениям пользователей из России оплата там может не проходить, а для free-моделей действуют лимиты. Если нужен платный доступ из РФ, существуют российские OpenAI-совместимые шлюзы с оплатой в рублях (например, Polza.ai). Перед выбором проверьте актуальные условия.
- Если ИИ недоступен или вернул мусор, сайт **не ломается**: сработает запасной генератор, а причина ошибки запишется в журнал (видна в панели).

Ключ хранится только на сервере и не попадает в браузер.

## Как это работает

**Кнопка → идея.** Браузер отправляет настройки (интересы, компания, бюджет, настроение), время суток и день недели. Сервер добавляет историю оценок этого пользователя («раньше понравилось / не понравилось», «недавно предлагали») и просит ИИ вернуть JSON: категория, название занятия, эмодзи, текст.

**Оценка.** Шкала от 1 до 5 с лицами. Запись `запрос → ответ → оценка` лежит в таблице `requests`. Оценку можно изменить. Кнопка «Пойду!» отдельно фиксирует, что идея принята.

**Геолокация и промокоды.** Спрашиваем разрешение. Координаты округляются до ~100 м. Предложение партнёра показывается, если:
- пользователь сейчас в радиусе партнёра (по умолчанию 300 м), или
- за последние 30 дней он как минимум в 2 разных дня бывал рядом (ходит мимо или посещает регулярно).

Чтобы не надоедать, один и тот же партнёр показывается не чаще 3 раз в сутки. Если рядом спортзал, ИИ с вероятностью 70% предлагает именно «потренироваться», и купон выглядит логичным продолжением. Копирование промокода тоже логируется (конверсия видна в панели).

**Показ без выхода из дома.** В «Настроить подборку» есть пункт «Демо: представить, что я рядом с партнёром». Он подставляет координаты спортзала и сразу показывает купон `mneskuchno` (скидка 50%).

**Панель разработчика** (`/admin.html`, вход по логину и паролю из переменных окружения; сессия подписана HMAC, живёт 8 часов, на вход есть ограничение попыток):
- вердикт «как справляется ИИ» (по средней оценке) и сильные и слабые категории;
- показатели: запросы, пользователи, средняя оценка, доля оценок 4–5 и 1–2, доля «Пойду!»;
- **предпочтения пользователей**: доля пользователей по любимой категории (вроде «5% любят прогулки, 94% — кафе»), плюс доля по интересам, отмеченным в настройках;
- **конкретные занятия**: топ-10 с долей от всех запросов (так видны и «кафе», и «быстрый перекус в фастфуде», и любые другие места, которые назовёт ИИ);
- ИИ против запасного генератора, распределение оценок, оценки по категориям, динамика за 14 дней;
- партнёры (добавление, выключение, удаление), показы и конверсия;
- журнал «запрос → ответ → оценка» с фильтрами и выгрузкой CSV.

## Что добавлено сверх исходной идеи

- **Экран меняет цвет**: пока идеи нет, он серый (скука), а после ответа заливается цветом категории.
- Кнопка **«Пойду!»**: показывает, сколько идей люди реально принимают, а не только оценивают.
- **Настройки подборки**: интересы, компания, бюджет, настроение. Их ИИ получает в запросе.
- **Адаптация по оценкам**: ИИ видит, что пользователю нравилось и не нравилось, и не повторяет недавнее.
- **Запасной генератор**: сайт работает даже без ключа ИИ или при сбое ИИ. В статистике ИИ и запасной генератор считаются раздельно.
- **Демо-режим без сервера** для GitHub Pages и **демо-данные** для пустой базы.
- В панели разработчика: управление партнёрами, конверсия промокодов, фильтры журнала, выгрузка CSV.

## База данных

Таблицы: `clients`, `requests`, `partners`, `location_pings`, `offers_log` (схема в `docs/schema.sql`). Это можно использовать в ЛР по диаграмме классов и модели БД.

## Безопасность и данные

- Нет сторонних зависимостей на сервере (меньше уязвимостей в цепочке поставок).
- Все SQL-запросы параметризованы, интерфейс строится без `innerHTML` (защита от XSS), включена политика CSP, выгрузка CSV защищена от формул-инъекций.
- Чужую оценку изменить нельзя: запись привязана к анонимному идентификатору браузера.
- Ограничение частоты запросов к генерации (20 в минуту с одного IP) защищает бюджет ИИ.
- Геопозиция запрашивается только с согласия, хранятся округлённые координаты и анонимный идентификатор, без имён и телефонов. В отчёте стоит упомянуть, что при реальном запуске понадобится политика обработки персональных данных (152-ФЗ).
